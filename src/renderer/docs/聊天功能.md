## AppUIMessage 类型解析

AppUIMessage 是渲染层自己的消息模型（`src/renderer/src/types/message.ts`），与内核的 `AgentMessage` 是两套表示：内核那份负责持久化与组装上下文，这份只描述界面要渲染什么。改聊天界面前先分清自己在哪一层，不要把内核字段直接搬过来。

```ts
interface AppUIMessage {
  id: string;
  role: 'user' | 'assistant' | 'system';
  parts: AppUIMessagePart[];
  usage?: Usage; // 只有助手消息有
}
```

需要记住的规则：

- 消息是 **part 序列**，不是一段文本。一次助手回复可能是"思考 → 工具调用 → 正文 → 工具调用 → 正文"，每个片段一个 part，顺序即渲染顺序；追加增量时落到最后一个同类型 part 上。
- 工具**调用与结果是两个 part**，通过 `toolCallId` 配对渲染成一行。结果不单独成消息，历史里被并入它前面那条助手消息。
- part 自带流式状态：正文与思考的 `state` 从 `streaming` 走到 `done`，用户打断则为 `abort`；从历史读出来的消息一律是 `done`。
- 跨 IPC 只传字符串：工具入参、工具输出都是 JSON 字符串，图片 part 只带落盘路径，渲染时拼 `app://`。
- 出错时往当前助手消息末尾追加 `error` part，用户打断时追加 `abort` part。

示例：用户提问 → 助手查目录 → 作答

```json
[
  {
    "id": "m-1",
    "role": "user",
    "parts": [{ "type": "text", "text": "第三章讲了什么？" }]
  },
  {
    "id": "m-2",
    "role": "assistant",
    "parts": [
      { "type": "reasoning", "text": "先查目录定位第三章", "state": "done" },
      {
        "type": "tool-call",
        "toolCallId": "call_a1",
        "toolName": "get_book_tocs",
        "input": "{\"bookId\":7}"
      },
      {
        "type": "tool-result",
        "toolCallId": "call_a1",
        "toolName": "get_book_tocs",
        "output": "{\"tocs\":[{\"id\":12,\"title\":\"第三章 记忆曲线\"}]}",
        "success": true
      },
      { "type": "text", "text": "第三章讲的是记忆曲线……", "state": "done" }
    ],
    "usage": { "input": 1240, "output": 188, "totalTokens": 1428 }
  }
]
```

## Trace概念

Trace 是**消息列表的划分单位**：一条用户消息，加上它之后、下一条用户消息之前的全部内容。
虚拟列表一行 = 一个 trace，底部的用量统计行与复制按钮也以 trace 为单位（统计只累加 trace 里的助手消息）。

划分规则（`groupMessagesIntoTraces`）：

- 遇到 user 消息就开一条新 trace，上一条就此结束——**user 消息是唯一的分行依据**。
- assistant 消息并入当前 trace。
- system 消息（目前只有上下文压缩提示）**就地插进当前 trace**，不单独占一行。所以 `Trace` 存的是有序的 `nodes`，而不是"用户消息 + 助手消息数组"。
- 归属不明的 assistant（出现在任何 user 之前）直接丢弃，不造没有用户消息的 trace。

压缩提示的位置按**时间顺序**，不做前移：压缩发生在两个 turn 之间，提示就出现在"上一轮回复之后、下一轮回复之前"；一次运行开始**之前**的压缩写在触发它的那条用户消息之前，于是落在**上一条 trace 的末尾**。历史回放与实时流式看到的顺序一致，照着日志读就行。

例：一次工具调用 + 一次压缩，共划出两条 trace

```
├─ 用户：第三章讲了什么？                ┐
│  助手：先查目录（tool-call / result）  │ trace A
│  助手：第三章讲的是记忆曲线……         │
│  系统：上下文已压缩                    ┘
├─ 用户：那第四章呢？                    ┐ trace B
│  助手：第四章讲的是遗忘曲线……         ┘
```
