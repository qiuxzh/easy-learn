# 会话管理需求

把自研 agent 内核（`src/main/agent`）的能力对接给前端，中间需要一层会话管理，代码位于 `src/main/chat`。前端只与这一层交互，不直接接触 agent 内核。

## 定位

- **会话**：一次持续的对话，持久化为 `agent_session` 一行及其 `agent_entry` 日志。库是会话内容的唯一真相。
- **会话 id**：由**前端生成**（`crypto.randomUUID()`），内核与外层都接受外部注入的 id，因此前端在新建时拿到的就是最终 id，不存在临时 id 与真实 id 的双重映射。
- **运行时**：主进程中活跃的会话实例，持有 Agent 与内存中的会话日志。运行态（是否正在生成）由主进程持有。

## 功能

### 创建会话

新建会话是**纯前端行为**：前端生成一个新的 sessionId 并进入空的对话视图，后端不感知，库中也不产生记录。

会话行由 `Chat_StreamSend` 在收到该会话的第一条消息时补建（详见下节），并顺手用首条消息的前若干字充当标题（压缩空白后截断）。这样"点了新建又离开"不会留下空会话，侧栏也不会出现空条目；相应地，尚无记录的会话不进侧栏、不可重命名，也不建立运行时。

"新建会话"点击即换用新 id；但若当前会话本就还没有任何记录（且不在生成中），再点不会重复新建。

### 重命名

用户可修改会话标题，标题仅用于列表展示。

### 会话列表与加载

- 列表按最近活跃（`updatedAt`）倒序展示，只含标题与时间，不加载消息内容。
- 打开某会话时读取其完整日志，用于渲染历史。

### 发送 prompt 与流式输出

- 用户发送消息后开始一次运行，助手回复以流式增量呈现。
- 生成过程中的增量不落库；一条消息生成结束时落库。
- 同一会话同时只允许一次运行。
- 思考级别由前端随消息带入，取 `off` / `medium` / `max` 三档之一，自下一次运行起生效。它属于单次请求的取值而非会话配置，因此**不进会话日志**；重开会话时由前端按当前选择重新带入。
- 系统提示同属单次请求的取值：每次运行前按本次请求的关联书籍现算（品类的基础提示词 + 书籍段落），同样**不进会话日志**。

### 中断

用户可随时停止正在进行的运行。已生成的内容保留并落库，会话回到可继续发送的状态。

### 切换会话

前端可在会话间切换。切换不得影响正在运行的会话：切走时运行继续，切回时能看到最新进展。

## 通道

### 前端 → 后端（请求-响应）

| 通道                      | 入参                                           | 返回                        | 后端职责                                                                                                                                                                                                                                                                                                                              |
| ------------------------- | ---------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Chat_ListSessionSummary` | —                                              | `SessionSummary[]`          | 读库按 `updatedAt` 倒序；每条附带 `isRunning`（查运行时池）。只含元数据，不加载消息内容                                                                                                                                                                                                                                               |
| `Chat_RenameSession`      | `{ sessionId, title }`                         | —                           | 改库                                                                                                                                                                                                                                                                                                                                  |
| `Chat_DeleteSession`      | `{ sessionId }`                                | —                           | 若会话在池中：先 `dispose()`（内部中断并等待落库）再从池中移除；**最后**删库行。顺序不可颠倒，否则运行中的会话后续落库会撞已删除的外键                                                                                                                                                                                                |
| `Chat_OpenSession`        | `{ sessionId }`                                | `{ summary, entries, run }` | 见下节。`sessionId` 必填                                                                                                                                                                                                                                                                                                              |
| `Chat_StreamSend`         | `{ sessionId, text, thinkingLevel?, bookId? }` | `{ sessionId }`             | 会话未落库时先建 `agent_session` 行（标题取 `text` 前若干字）；取得（或建立）运行时，`thinkingLevel` 随这次组装一并传入；随后按 `bookId` 现算系统提示并写入运行时；最后发起运行。`thinkingLevel` 缺省视作 `medium`；`bookId` 缺省表示本次提问不关联书籍（提示词里不带书籍段落）。**立即返回**，不等待运行结束；运行期错误通过事件上报 |
| `Chat_StreamAbort`        | `{ sessionId }`                                | `{ success }`               | 中断该会话正在进行的运行，`success` 表示是否确实有运行被中断。会话不在池中时不做任何事（幂等）                                                                                                                                                                                                                                        |

### 后端 → 前端（推送）

| 通道         | 载荷                   | 说明                                       |
| ------------ | ---------------------- | ------------------------------------------ |
| `Chat_Event` | `{ sessionId, event }` | 会话事件流：消息开始/增量/结束、工具执行等 |

事件由运行时建立时订阅内核得到，推送给所有渲染窗口。**所有会话的事件都会推送**，不区分前端当前打开了哪个会话——后端不感知前端的打开状态。

### 打开会话

`Chat_OpenSession` 返回一次已落库会话的完整信息，`sessionId` 必填：

| 情形     | 处理                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 池中已有 | 直接返回内存中的日志与运行态                                                |
| 池中没有 | 从库中读出完整日志返回，不建立运行时、也不放入池中                          |
| 正在运行 | 同"池中已有"，额外带上 `run.streamingMessage`——正在生成但尚未落库的那条消息 |

返回值 `{ summary, entries, run }`：`summary` 供侧栏刷新条目，`entries` 是已落库的完整日志，`run` 是运行态快照 `{ isRunning, streamingMessage? }`。传入库中不存在的 `sessionId` 属于无效请求（已被删除的会话不会到达前端）。

**打开会话不建立运行时**：浏览历史只需读日志，建立运行时会白算一遍给模型用的上下文，还会让运行时池随浏览无限增长。真正需要运行时的时机是 `Chat_StreamSend`。

### 前端契约

- `Chat_Event` 必须是**常驻的全局监听**（应用启动即监听，不随开关会话变化），否则会话关闭期间的事件会丢失。若改为按需监听，则必须在调用 `Chat_OpenSession` **之前**开始监听。
- 前端按会话日志的 `id`/`seq` 去重合并：请求-响应与推送走不同通道，顺序不保证，去重才能避免重复或缺口。
- 前端的消息缓存可丢弃，判定条件为"未被任何对话视图占用且不在生成中"，在"切走"与 `agent_end` 两个时机各判一次。正在生成的会话切走后保留，切回时无缝续看；其余情况丢弃以保持内存有界。丢掉的会话重新打开时靠 `Chat_OpenSession` 的全量日志 + 运行态快照恢复，之后继续消费事件——因为快照含 `streamingMessage`，恢复是无损的。

### 前端改造点

- **事件类型转换**：内核 `message_update` 携带的 `assistantMessageEvent` 本身已含增量（`text_delta` / `thinking_delta` / `toolcall_delta`，并带 `contentIndex`），前端据此增量追加到对应 part，不做事后快照 diff；工具调用与结果由 `toolcall_end` 与 `tool_execution_end` 独立成 part/消息，不再从 assistant 消息的 parts 里挖。需要一层"事件 → 界面消息"的转换。
- **运行态来源**：`isStreaming` 不再由前端在发送/结束时自行置位，改由 `agent_start` / `agent_end` 维护。
- **消息缓存的键**：会话 id 即前端生成的最终 id，直接作为缓存键，无需与真实 id 互映。

## 暂不涉及

- **steering / followup**（运行中插话、追加后续）：后续迭代。
- **分支 / fork**（从历史某点重新生成）。
- **标题自动生成**：现取首条消息前若干字，用模型改写标题另行安排。
- **悬空 toolCall**：被中断的运行会留下没有对应工具结果的工具调用，恢复历史时有兼容问题，另行安排。
- **多书关联**：`Chat_StreamSend` 的 `bookId` 目前是单值，只用于生成系统提示里的书籍段落；一次关联多本书待后续。
- **模型切换**：会话中途换模型需要同步写入日志，接口与前端入口都还没有。
