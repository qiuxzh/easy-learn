# 浮层内弹层被遮挡（z-index 分层）

## 问题

在常驻浮层（如闪卡助手）里点开思考强度选择器、下拉菜单、Select 等弹层，弹层**完全看不见**，表现为"点了没反应"。控制台无报错。

## 根因

弹层组件（Radix / base-ui）各自 Portal 到 `document.body`，与浮层变成 **body 下的兄弟节点**。

原本"弹层在浮层里面"的嵌套关系在 DOM 中丢失，谁盖谁只能靠 z-index 数字比大小。浮层若写 `z-50`，弹层又是 `z-auto`，浮层就会盖住自己的弹层。

## 彻底解决方案（未来实现）

当前用令牌只解决了"谁盖谁"，属于够用的当前解。弹层复杂到一定程度后，正确做法是**统一 portal 容器 + 层级栈**，能顺带解决出于 z-index 机制本身、令牌无法表达的问题。

思路分两步：

1. **统一挂载点**。所有弹层 Portal 到同一个容器节点（Radix 与 base-ui 的 Portal 都支持 `container` prop），而不是各自挂 `document.body`。容器整体设一个层级，弹层之间不再需要各自比 z-index。
2. **栈管理顺序**。容器维护一个按打开顺序排列的栈，后开的在上，关闭时出栈。

第 2 步是关键，因为它提供的是 **z-index 里根本不存在的信息——顺序**。z-index 只是绘制顺序，没有任何"谁开着、谁后开的"记录。因此下面这些需求**只能靠栈实现**：

- 点外部只关**最上层**的那个，保留下面的
- Esc 逐层关闭
- 焦点锁定在最上层，下层设为 inert
- 判断"某个弹层是否是最上层"来决定是否响应快捷键

**实现时机**：出现第二个常驻浮层，或发现弹窗里的下拉菜单被盖住（同层撞车），或需要上面任一交互时。

## 规则

层级令牌定义在 `src/renderer/src/index.css` 的 `@theme` 里：

| 令牌        | 值  | 用途                         |
| ----------- | --- | ---------------------------- |
| `z-panel`   | 40  | 常驻浮层：可移动缩放的"窗口" |
| `z-popover` | 50  | 依附触发器的临时弹层         |

**新增浮层用 `z-panel`，临时弹层用 `z-popover`。** 两者名字里已写死先后关系，不要再写数字。

注意 Tailwind v4 的令牌命名空间是 `--z-index-*`，写成 `--z-panel` 不会生成任何类名，且**不会有任何报错**——必须构建后确认 CSS 里真的出现了对应类名。

## 当前方案的局限

令牌只约定顺序，**不保证每个弹层遵守**。`ui/` 下的 Radix 弹层仍各自 portal 到 body，同层（都是 `z-50`）时先后顺序取决于插入 body 的顺序，不可控。

也就是说，令牌能防住"浮层盖住自己的弹层"，但防不住弹层之间的互相遮挡。后者需要上面那套彻底方案。
